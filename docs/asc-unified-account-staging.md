# ArcScriptCenter Account staging QA

The account preview is opt-in through `sandbox/ASCAccountLoaderPreview.lua`. It preserves the existing ESLogin layout. Login and registration take place on the account website. ESLogin displays a five-minute one-use pairing code. The website confirms the link after authentication, including 2SV when enabled. The Executor polls using a separate random secret, then validates the resulting scoped session with the Worker before opening SetUp. Roblox Studio can reuse ESLogin with an injected transport and PlayerGui parent. A Roblox Studio account transport is outside this preview.

Browsing the account site uses an HttpOnly, Secure, SameSite=Strict cookie. The Loader credential grants only authenticated Loader operations, including the owner's cases. It cannot change account security or profile settings. Remember stores that revocable credential and its expiry in `ArcScriptCenter/Account.json`. Executor file storage is readable by the local host and Executor; use session-only mode on shared or untrusted devices. The Loader credential expires in four hours, or 12 hours with Remember. After a logout or expiry in an already running Loader, rejoin and launch the preview again to initialize new UI handlers. With Remember off, pair again after rejoining. The website's Active Sessions setting can revoke an individual session.

Active presence is recorded with the account ID and a heartbeat every 30 seconds from the running Loader. An account counts once across sessions and drops from the internal count 90 seconds after its last heartbeat. Public online visibility is separate. No hardware identifiers or client-asserted Roblox identity are used. Profile nicknames are visible to their owner in this preview. If a future feature shares them with other Roblox players, it must add Roblox text filtering before display. For a configured image or banner, the Worker checks for an available public Roblox thumbnail. The native preview uses the original logo and the selected banner color as fallbacks.

## Offline Passkey recovery and secondary-credential reauthentication — 2026-11-24

This section updates the earlier note that isolated Passkey QA lacked recovery. **Recovery and backup functionality is implemented and undergoing QA only; it has not been deployed to the live Account Worker and the launch flag remains absent.**

- Initial successful, UV-required ES256/P-256 Passkey registration now generates **eight independent 128-bit offline recovery codes** (32 lowercase hex digits each). The Account QA D1 stores only SHA-256 digests in `asc_account_passkey_recovery_codes`. The raw codes appear once in the registration response, are rendered once on the QA website, and are never added to GitHub, logs, telemetry or a Roblox client.
- A one-use `passkey/recovery/options` flow requires the username, a valid unspent recovery code, a successful Turnstile token with **action `asc_recover`**, and the bound browser cookie. It creates a fresh WebAuthn registration challenge with exact Origin, RP ID and user verification. `passkey/recovery/verify` consumes the challenge once; only a valid signed authenticator registration activates recovery. Successful recovery **replaces old Passkeys**, revokes existing Account Sessions, increments the Account epoch, invalidates every old recovery code, and issues eight fresh one-time codes. Account Cases and moderation status are preserved.
- Adding a second Passkey uses `passkey/backup/options` → `passkey/backup/verify-current` → `passkey/backup/verify`. An existing **server-validated web session** is required throughout, *plus* a fresh signed assertion from a currently registered, user-verified Passkey before registering another credential. The new credential is added without deleting the old one; a browser session without that fresh assertion is insufficient. Flows are account- and session-bound in `asc_account_passkey_backup_flows` and expire in 5 minutes; up to five credentials are supported.
- New migration files `migrations/asc_passkey_recovery_ISOLATED_QA_ONLY.sql` and `migrations/asc_passkey_backup_ISOLATED_QA_ONLY.sql` were applied **only** to D1 `asc-stage1684-identity-sandbox-20261117` after confirming 0 Account rows.
